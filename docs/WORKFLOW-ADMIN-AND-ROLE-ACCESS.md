# اصل اجرای گردش‌ها با مدیر سامانه و دسترسی نقش‌ها

## اصل پروژه

مدیر سامانه باید بتواند گردش کامل هر فرایند را از ماژول مالک همان فرایند جلو ببرد؛ برای نمونه بررسی فنی در برنامه تأمین، رسید در انبار و تأیید دریافت در گردش مواد. این امکان برای آزمون و نظارت است و نباید گردش موازی یا دکمه‌ای بسازد که کنترل‌های عادی فرایند را دور بزند.

هر عملیات با هویت واقعی فرد واردشده ثبت می‌شود. مدیر سامانه اگر مرحله‌ای را انجام دهد، عامل همان مدیر است؛ سامانه نباید وانمود کند تحقیق‌وتوسعه، مالی، انبار یا مدیرعامل آن اقدام را انجام داده‌اند. تأیید مالی، فنی و مدیریتی نیز با قواعد و سابقهٔ فعلی خود باقی می‌ماند.

دسترسی کارکنان پس از تثبیت گردش، بر مبنای نقش و حداقل نیاز تعریف می‌شود. برای هر نقش باید جداگانه مشخص باشد چه ماژولی را می‌بیند، چه پرونده‌هایی را می‌خواند، چه عملیاتی را ثبت می‌کند و چه تصمیم‌هایی را تأیید می‌کند. پنهان‌کردن آیکون به‌تنهایی مجوز دسترسی محسوب نمی‌شود؛ سرور باید خواندن و نوشتن را کنترل کند و رابط، HTTP و MCP از همان قواعد پیروی کنند.

## ترتیب اجرا

1. **مرور مسیر موجود:** مراحل، مالک ماژول، ورودی/خروجی و نقاط تصمیم هر فرایند را ثبت کنید؛ گردش‌های موجود را از طریق ماژول خودشان پیش ببرید.
2. **آزمون انتها‌به‌انتها با مدیر:** مسیر عادی، برگشت برای اصلاح، رد، توقف، تکرار ثبت و تغییر اطلاعات میان مراحل را با دادهٔ آزمایشی بررسی کنید. پیش‌نیازها و تأییدها را حذف نکنید.
3. **ثبت سابقهٔ قابل اتکا:** برای هر تغییر عامل واقعی، زمان، مرحله، تصمیم و دلیل را نگه دارید. اجرای مدیر، تأیید نقش دیگر شمرده نمی‌شود.
4. **تعریف ماتریس دسترسی:** برای هر نقش، ماژول‌های لازم و عملیات مجاز را بنویسید؛ دسترسی به پرونده‌های نامرتبط، اطلاعات حساس و تنظیمات مدیریتی را پیش‌فرض ندهید.
5. **اعمال دسترسی در سرور و رابط:** API و ابزارهای MCP باید همان مجوزهای سمت سرور و کنترل‌های دامنه را داشته باشند. رابط فقط کارهای مجاز را نشان دهد.
6. **آزمون جداگانهٔ نقش‌ها:** بعد از آزمون مدیریتی، هر نقش را با حساب واقعی خودش بررسی کنید: موارد لازم قابل مشاهده/اجرا باشند و کارهای بیرون از مسئولیت رد شوند.
7. **بازبینی پیش از انتشار:** نتایج آزمون، موارد مسدود، تأییدهای لازم و تغییرات دسترسی را مستند کنید. دادهٔ آزمایشی را با اسناد مالی، پرداخت یا موجودی واقعی مخلوط نکنید.

## معیار پایان هر فرایند

- مدیر سامانه می‌تواند مرحله‌ها را از ماژول‌های مربوطه طی کند، بدون دور زدن اعتبارسنجی یا ترتیب گردش.
- تمام تصمیم‌ها به عامل واقعی منتسب‌اند و قابل پیگیری هستند.
- هر نقش فقط داده و عملیاتی را می‌بیند که برای کارش لازم است؛ محدودیت هم در سرور اعمال می‌شود.
- مسیرهای HTTP و MCP همان قواعد مجوز، اعتبارسنجی، تأیید و ثبت سابقه را اجرا می‌کنند.
- آزمون هر نقش با حساب همان نقش انجام شده و با آزمون مدیریتی اشتباه گرفته نشده است.
