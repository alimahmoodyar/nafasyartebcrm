# تقویم هم‌نفس

همه ورودی‌ها و نمایش‌های ساختاریافته تاریخ در رابط کاربر، هجری شمسی هستند. ساعت‌ها به وقت تهران‌اند؛ تنظیم تقویم یا منطقه زمانی مرورگر نباید روز را جابه‌جا کند. متن آزاد و محتوای فایل‌های بارگذاری‌شده بازنویسی نمی‌شوند.

- `lib/persian-date.ts`: قالب‌بندی تاریخ/ساعت، ماه شمسی، تبدیل معتبر شمسی به ISO، پذیرش ارقام فارسی/عربی/انگلیسی و تشخیص روز تهران.
- `SolarDate`: روز، ماه و سال شمسی؛ مقدار خروجی ISO. اختیاری‌ها قابل پاک‌کردن‌اند؛ تاریخ نامعتبر به امروز تبدیل نمی‌شود. تغییر ماه/سال، روز را در صورت نیاز به آخرین روز معتبر همان ماه محدود می‌کند.
- تاریخ متنی اکسل باید سال/ماه/روز باشد، مانند `۱۴۰۵/۰۷/۱۱`. تاریخ استاندارد Excel و داده‌های ISO قدیمی نیز پذیرفته می‌شوند. عدد خام ناشناخته، تاریخ نامعتبر یا فرمت مبهم تبدیل حدسی نمی‌شود.
- `get_calendar_context` در MCP/دستیار، تاریخ امروز تهران و تبدیل دقیق دسته‌ای را فراهم می‌کند. زمان‌های مهلت API همچنان ISO با offset تهران هستند.
- تاریخ‌های دیتابیس، payloadهای API و `previous` برای قفل همزمانی ISO باقی می‌مانند. هیچ مهاجرت یا بازنویسی سوابق لازم نیست. فایل خروجی پشتیبان، records اصلی و displayRecords شمسی مستقل دارد.

## بررسی

`tests/persian-dates.cjs` با TZ تهران و لس‌آنجلس اجرا شد: اسفند کبیسه، رد روز نامعتبر، نیمه‌شب ایران، ورودی اکسل، حفظ نسخه اصلی داده، کل بازه نمودار و رندر انتخاب‌گر خالی/نامعتبر. TypeScript و مجموعه‌های after-sales، sourcing، duties، inbox، assistant و mcp-integration موفق‌اند؛ ابزار تبدیل و پیش‌نمایش تاریخ شمسی توزیع از مسیر MCP هم بررسی شدند.

دو مجموعه قدیمی `distribution.cjs` و `serials.cjs` پیش از رسیدن به سناریوها، به‌دلیل fixture قدیمی نماینده بدون serviceAgentId و نگاشت قدیمی password-auth متوقف می‌شوند؛ نباید به‌عنوان تست موفق این انتشار گزارش شوند. نگاشت تقویم در loaderهای قدیمی اضافه شده، اما بازسازی آزمون‌های قدیمی احراز هویت جزو این تغییر نیست. تست انسانی در مرورگر تولید انجام نشده است.
