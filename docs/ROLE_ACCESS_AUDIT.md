# گزارش بررسی دسترسی نقش‌ها

تاریخ: ۲۰ مهر ۱۴۰۵ (2026-10-11)
شاخه: sites/nafasyar-trace

## دامنه و نتیجه

بررسی قبلی برای اثبات تمام دسترسی‌ها کافی نبود. آزمون جدید `tests/role-access-audit.cjs` همه ۵۵ نقش قابل انتخاب را با انتظارات مستقل از جدول تولید مجوز بررسی می‌کند: ۴۶۰۲ کنترل مثبت و منفی موفق.

| حوزه | کنترل‌های انجام‌شده |
| --- | --- |
| رهگیری و تولید | مشاهده و ثبت هر ۸ ماژول؛ مجوز هر ۵ مرحله رویداد تولید؛ ویرایش محصول و firmware |
| مالی | استقلال خزانه‌دار، مدیر مالی، رئیس حسابداری و مجوز نهایی مدیرعامل؛ نبود اختیار مرحله برای سایر نقش‌ها |
| فروش | مدیر، کارشناس، حسابداری فروش؛ عدم اعطای اختیار مدیر به کارشناس |
| خرید و تأمین | هر نقش تأمین و بازرگانی؛ محدوده انبار انتخابی و انبار خط |
| خدمات | حوزه خانگی/بیمارستانی مستقل؛ نقش‌های زیرمجموعه خدمات؛ اختیارات اختصاصی بیمارستان |
| پرسنلی و اموال | استقلال نقش‌های اداری، حقوق، تأیید، مالی و پرداخت؛ اموال‌دار |
| کیفیت | مجوز نوشتن هر نوع پرونده؛ نقش تحقیق‌وتوسعه و مدیرعامل برای طراحی خصوصی؛ منع مشاهده خصوصی برای سایر نقش‌ها |
| تدارکات | مدیر حمل‌ونقل و راننده |
| حساب‌ها و دستیار | منع مدیریت کاربران و تنظیمات مدیر سامانه برای نقش‌های عادی؛ صفحات کیفیت و بیمارستان؛ حذف نقش و رد مجوزهای اضافی جعل‌شده |

آزمون ماتریس، توابع واقعی سیاست و دامنه را در پایگاه SQLite مجزا اجرا می‌کند. این به معنای اجرای هر درخواست ممکن روی هر endpoint، آزمون همه ترکیب‌های نقش یا بررسی داده و کاربران واقعی نسخه آنلاین نیست. آزمون‌های API و MCP زیر پوشش تکمیلی دارند.

## اصلاح‌ها

۱. هیچ نقش شغلی غیرادمین امکان تعریف شناسنامه محصول و BOM پایه را نداشت. نقش مستقل `product_manager` فقط مشاهده و ثبت محصول دارد؛ دسترسی عملیات انبار، تولید یا طراحی خصوصی نمی‌دهد. مدیر سامانه باید آن را صریحاً به مسئول مربوط تخصیص دهد. نقش‌ها و حساب‌های فعلی خودکار گسترش داده نشدند.

۲. فهرست و کنترل صفحات دستیار فاقد صفحات کیفیت و بیمارستان بود؛ با سیاست صفحه اصلی هماهنگ شد. این تغییر صرفاً دسترسی ناوبری مجاز را برقرار می‌کند؛ مجوز عملیات در دامنه بررسی می‌شود.

## آزمون عمومی و محدودیت‌ها

۴۸ مجموعه آزمون اجرا شد: ۳۹ موفق، ۹ ناموفق. ماتریس جدید جداگانه موفق است. آزمون‌های موفق شامل حساب‌های رمزدار، HTTP/MCP، گردش مواد، تولید، کیفیت سازمانی، خدمات خانگی و گارانتی، فروش و شبکه فروش، خرید داخلی/خارجی، مالی خرید، خدمات خرید و تسویه، خزانه‌داری و ضمانت‌نامه، پرسنلی و مساعده، حمل‌ونقل، هزینه، اموال، پروژه و تولید روزمره، کارتابل، راهنمای فرایند، یادآوری، فعال‌سازی، ریست و فرم‌های دستیار هستند.

خطاهای باقی‌مانده:

- `quality`, `firmware`, `finance-control`: بارگذار قدیمی آزمون وابستگی `./qms-contract` را تأمین نمی‌کند؛ آزمون به کنترل کسب‌وکاری نمی‌رسد.
- `replenishment`: ورودی آزمایشی دریافت جزئی، شرح الزامی مغایرت تعداد را ندارد و با ۴۰۰ رد می‌شود.
- `sales-leads`: آزمون رد دسترسی، ۴۰۳ انتظار دارد ولی ۴۰۹ دریافت می‌کند؛ علت کامل هنوز تعیین نشده است.
- `hospital`, `hospital-field`, `training`: آماده‌سازی آموزشی در محاسبه پیش‌فاکتور خطا می‌خورد؛ علت کامل هنوز تعیین نشده است.
- `hospital-expenses`: علاوه بر خطای آماده‌سازی آموزش، آزمون رد دسترسی ۴۰۳ انتظار دارد ولی ۴۰۹ دریافت می‌کند؛ نیازمند پیگیری است.

هیچ کنترل امنیتی برای سبزکردن آزمون‌ها حذف یا ضعیف نشد. بنابراین نتیجه کل آزمون عمومی موفق کامل اعلام نمی‌شود. نسخه آنلاین منتشر یا داده‌های واقعی تغییر داده نشده‌اند.
