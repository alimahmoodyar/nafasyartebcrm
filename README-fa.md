# تحویل سامانه نفس‌یار — بک‌اند .NET 8

این بسته مستقل شامل فرانت React/TypeScript، بک‌اند ASP.NET Core 8 با C# و دیتابیس SQLite است. وب‌سرور Node و ورود ChatGPT در این نسخه استفاده نمی‌شوند. سورس فرانت و بک‌اند قابل ویرایش است؛ نسخه آماده نیز در ready-to-run قرار دارد. لینک سایت قبلی با این خروجی تغییر نکرده است.

## ورود و مدیریت کاربران

نام کاربری و رمز اولیه در LOGIN.txt است. بعد از اولین ورود باید رمز را عوض کنید؛ تا آن زمان APIهای کاری و ساخت همکار مسدودند. «حساب / تغییر رمز» بالای برنامه، تغییر نام کاربری و رمز خودتان را با دریافت رمز فعلی انجام می‌دهد. بعد از تغییر دوباره وارد شوید.

مدیر در همین صفحه حساب همکار را با نام، واحد، ایمیل، نام کاربری، رمز اولیه و مجوزها ایجاد می‌کند. برای هر بخش مشاهده و ثبت/ویرایش جداست؛ برای رویداد تولید، مرحله مجاز را نیز انتخاب کنید. دسترسی وابسته لازم به صورت خودکار افزوده می‌شود. بازنشانی رمز و غیرفعال کردن حساب از همین صفحه ممکن است. رمز همکار قابل مشاهده نیست؛ فقط بازنشانی می‌شود. همکار نیز باید رمز اولیه یا بازنشانی‌شده را عوض کند. نام کاربری انگلیسی ۳ تا ۴۰ نویسه و رمز ۱۲ تا ۲۵۶ نویسه است. ایمیل مالک در تنظیمات ثابت است؛ نام کاربری ورود را می‌توانید تغییر دهید. حساب همکار، مدیر کل نمی‌شود.

## اجرای سریع برای همکار برنامه‌نویس

۱. ASP.NET Core Runtime 8 را نصب کنید؛ برای تغییر و بیلد بک‌اند SDK 8 لازم است. نسخه آماده framework-dependent است و runtime را در خود ندارد.
۲. پوشه بسته را در محل خصوصی سرور استخراج کنید. فقط wwwroot محتوای عمومی است؛ هرگز کل پوشه بسته یا فایل دیتابیس را به عنوان web root معرفی نکنید.
۳. وارد ready-to-run شوید. قبل از اولین اجرای عادی، داده را وارد کنید:

```sh
cd ready-to-run
dotnet Nafasyar.Api.dll --import ../data/production-export.json
dotnet Nafasyar.Api.dll --check
dotnet Nafasyar.Api.dll
```

۴. در همان رایانه http://localhost:5080 را باز کنید. این آدرس برای آزمایش محلی است. در ویندوز همین فرمان‌ها در PowerShell اجرا می‌شوند. App_Data در پوشه اجرای برنامه ساخته می‌شود؛ برای سرور مسیر دائمی بیرون پوشه انتشار تنظیم کنید.

## انتشار روی دامنه شرکت

در ready-to-run/appsettings.json مقدار PUBLIC_ORIGIN را دقیقاً برابر https://trace.example.com (بدون / آخر) قرار دهید. DATA_DIR را مسیر مطلق دائمی مثل /var/lib/nafasyar بگذارید. TRACE_OWNER_EMAIL را پیش از اولین راه‌اندازی بررسی کنید؛ تغییر آن بعداً انتقال مالکیت محسوب نمی‌شود. Urls را http://127.0.0.1:5080 نگه دارید. مقادیر از متغیر محیطی هم قابل تنظیم‌اند.

یک reverse proxy با گواهی HTTPS معتبر به پورت 5080 وصل کنید. نمونه Nginx و systemd در deploy است. کاربر سرویس باید مجوز نوشتن DATA_DIR داشته باشد. فرایند با working directory برابر ready-to-run اجرا شود. origin درخواست مرورگر با PUBLIC_ORIGIN تطبیق داده می‌شود؛ پشت پروکسی نیز باید دامنه واقعی تنظیم شود. لاگین و تغییر رمز ۲۰ درخواست در دقیقه برای هر IP محدود شده‌اند؛ پشت یک پروکسی فعلاً این سقف بین کاربران مشترک است. هدر IP ارسالی اینترنت عمداً مبنای اعتماد نیست.

برای Docker، compose.yaml را با دامنه و ایمیل خود تنظیم و سپس docker compose up -d --build اجرا کنید. قبل از نخستین اجرای وب، ورود داده را با docker compose run --rm app --import /seed/production-export.json انجام دهید. volume داده را حذف نکنید. دیتابیس SQLite برای یک نمونه سرویس روی یک سرور با دیسک محلی طراحی شده؛ استقرار چند replica یا قرار دادن DB روی share شبکه انجام ندهید.

## داده همراه بسته

فایل production-export.json، تصویر واقعی خروجی نسخه ۱۱ در 2026-09-13T15:24:05Z است؛ به‌روزرسانی زنده تا زمان دریافت این بسته نیست. در آن زمان رکورد عملیاتی شرکت، همکار، فایل HEX و سریال رزروشده ثبت نشده بود؛ فقط شناسه مالک موجود است. بنابراین خالی بودن جدول‌های عملیاتی عمدی است. demo-records.json اطلاعات نمونه جداگانه است و فرانت نیز نمای نمونه دارد؛ آن را به عنوان داده واقعی وارد نکنید. اگر پس از تاریخ فوق اطلاعات وارد کرده‌اید، قبل از انتقال نهایی خروجی تازه بگیرید.

واردکننده فقط روی جدول‌های عملیاتی خالی کار می‌کند و همه جدول‌ها را در یک تراکنش وارد می‌کند. رمزهای ورود ChatGPT یا رمزهای بسته Node به این بسته منتقل نمی‌شوند؛ حساب‌های این بسته مستقل‌اند. برای انتقال فایل HEX از خروجی‌های بعدی، در کنار دیتابیس باید فایل‌های objects نیز منتقل شوند.

## توسعه و ساخت

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm build
cd ../backend
dotnet restore --locked-mode
dotnet build -c Release
dotnet publish -c Release -o ../ready-to-run
```

برای فرانت Node 22.13 یا بالاتر (بیلد تحویلی با Node 24) و pnpm مطابق package.json نیاز است. بیلد فرانت خروجی backend/wwwroot را جایگزین می‌کند. اجرای backend به Node وابسته نیست. فایل‌های C# بر اساس مسئولیت جدا شده‌اند؛ model-spec.json قرارداد اعتبارسنجی و نمایش است. تغییر فیلدهای دامنه باید هم در frontend/lib/model.ts و هم در model-spec.json هماهنگ شود. قراردادهای HTTP در Program.cs قرار دارند. migrationهای اجراشده را تغییر ندهید؛ migration جدید اضافه کنید. برای توسعه تیمی بسته را در مخزن خصوصی Git قرار دهید و DATA_DIR، رمز bootstrap و فایل‌های داده واقعی را commit نکنید.

## پشتیبان و بازیابی

```sh
dotnet Nafasyar.Api.dll --check
dotnet Nafasyar.Api.dll --backup /backup/nafasyar-2026-09-14
```

مقصد باید پوشه جدیدی بیرون DATA_DIR باشد. پشتیبان از API SQLite استفاده می‌کند و objects را نیز کپی می‌کند؛ برای یک نقطه بازیابی کاملاً ثابت، سرویس وب را هنگام پشتیبان متوقف کنید. کلیدهای cookie عمداً در پشتیبان فرمانی قرار نمی‌گیرند؛ بازگردانی به پوشه تازه ورود مجدد می‌خواهد. برای بازیابی، سرویس را متوقف کنید، پوشه پشتیبان را در DATA_DIR تازه قرار دهید و --check را اجرا کنید. فایل nafasyar.sqlite را با حساب سیستم محدود نگه دارید؛ رمزها هش هستند ولی داده‌های تجاری داخل دیتابیس رمزگذاری نشده‌اند.

اگر رمز مدیر فراموش شد، مسئول دارای دسترسی سرور از پوشه اجرا:

```sh
dotnet Nafasyar.Api.dll --set-password dr.aliebrahimi1368@gmail.com
```

رمز در ترمینال مخفی دریافت می‌شود؛ تغییر آن در ورود بعدی لازم است. bootstrap-admin.json فقط وقتی هنوز هیچ حساب محلی وجود ندارد خوانده می‌شود؛ تغییر این فایل رمز حساب موجود را عوض نمی‌کند. پس از اولین راه‌اندازی موفق آن را از سرور حذف کنید و نسخه تحویل را خصوصی نگه دارید.

## اعتبارسنجی و محدوده

tests/integration.py آزمون HTTP واقعی با دیتابیس موقت است: ورود اولیه، تغییر اجباری رمز، ساخت همکار و rollback تکرار نام کاربری، مجوز سمت سرور، بازنشانی/قطع دسترسی، محصول و دستگاه، کنترل بچ، تداخل ویرایش، سریال همزمان و idempotency، توزیع، HEX و بقای داده پس از restart. پس از build از ریشه بسته اجرا کنید: python3 tests/integration.py. برای مسیر غیرپیش‌فرض dotnet متغیر DOTNET را تعیین کنید.

این خروجی روی محیط Linux با .NET 8 کامپایل و آزمون شده؛ نصب واقعی روی سرور شرکت، HTTPS، چاپگر شما، مرورگر و حجم واقعی داده هنوز آزمون پذیرش همکار شما را می‌خواهد. Windows و Docker در این محیط اجرا نشده‌اند. این بسته مهاجرت فنی است و ادعای تکمیل همه نیازهای شرکت ندارد.

فرمول اختصاصی کد فعالسازی گارانتی هنوز دریافت نشده، پس صدور واقعی کد پیاده‌سازی نشده است. تاریخ گارانتی فقط از سابقه صدور موفق خوانده می‌شود و فروش/ورود اکسل آن را ایجاد نمی‌کند. اتصال همکاران سیستم و دستیار هوش مصنوعی نیز هنوز وجود ندارد.
